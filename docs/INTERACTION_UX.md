## 1. 使用方式

| 场景                   | 操作                             | 行为                                                                           |
| ---------------------- | -------------------------------- | ------------------------------------------------------------------------------ |
| 初次使用，尚未选择项目 | 直接发送任务需求                 | 保存需求并显示项目选择卡；点击可执行项目后提交原需求，无需重发                 |
| 已选择项目或话题       | 直接发送文字                     | 在当前项目开始任务，或在当前 Gateway 会话继续一轮                              |
| 继续旧话题             | 点击该卡片「接着聊」             | 显示当前项目、话题和后续消息去向；下一条普通消息继续该话题                     |
| 开启独立任务           | 点击「新话题」，或发送 `/新话题` | 保留项目、清除会话关联；下一条消息新建独立会话                                 |
| 切换项目               | 点击「切换项目」，或发送 `/项目` | 项目卡支持分页，显示可执行、只读和路径失效；点击可执行项目后开启新话题         |
| 查看技术信息           | 点击「查看详情」                 | 独立展示任务 ID、目录、thread/turn、状态、错误和结果；不会执行模型任务         |
| 明确回复某条任务       | 使用飞书引用回复任务卡或其详情卡 | 使用该卡片对应会话，优先于当前选择                                             |
| 第一条任务尚未建立会话 | 继续发送后续消息                 | 持久化消息并绑定原任务，等待其会话建立后入队；切换项目不会改变已保存消息的归属 |
| 正在执行时发送普通消息 | 直接发送文字                     | 在同一会话排队继续下一轮，不自动调用 steer 或 interrupt                        |

“接着聊”和“新话题”只改变后续消息去向，本身不会提交模型任务，也不会取消已排队任务。项目切换同样不会撤销此前保存的消息。

任务卡主体展示话题、项目、状态、本轮需求（与话题不同时）、执行提示及结果摘要。正文仍按纯文本安全转义，不能将模型输出里的链接/标记变成审批操作。技术 ID 和目录移到详情；审批、输入和错误提示继续显示。标题中的 `GW-…` 与正文回执仍保留，用于未知发送结果的核对。

第一批保留所有旧命令。立即补充仍使用 `/补充`，回答问题仍使用 `/回答`；卡片输入框、补充引导、最近任务和自然语言控制入口属于后续批次。

## 2. 路由与持久性

- 项目选择按钮只携带随机 nonce。实际项目、需求、任务和分页信息从服务器已保存的动作读取，校验应用、租户、用户、单聊和原消息 ID。
- 未选项目的每条消息对应一条独立需求草稿，互不覆盖。相同消息去重；重复按钮或同一需求的不同项目按钮不会再次提交。
- 草稿选择有效期 24 小时，单个用户/单聊最多 100 条未过期待选择需求。取消、过期或撤销项目写权限后不能提交旧需求。
- 点击项目时重新校验写权限和规范目录。自动发现的项目只读，目录失效不提供执行按钮；同名项目的按钮附带项目 key 区分。
- 创建任务、附加目标单聊、消费草稿和标记命令完成处于同一事务。事务失败会整体回滚，原消息继续留存；发送失败沿用 outbox 核对策略。
- 普通消息首次解析后持久化其目标项目和任务，后续重试不重新读取最近选择。等候会话绑定期间每秒重新检查，不增加失败次数；最多等待 24 小时，原任务未能建立会话时明确告知本条消息尚未执行。
- 恢复旧消息不会把用户之后选择的新项目或新话题切回去。未知执行结果继续沿用原锁和恢复规则，不推测为未执行，不自动重跑。
- 项目发现失败时仍提供已配置项目，明确提示发现不可用；不会将发现失败解释成用户没有项目。
- 草稿正文沿用内容保留策略，在过期且满足清理条件后移除，保留身份和状态。仍在等待后续消息处理的原任务正文不提前清除。

当前仍限定为一个授权用户和专用单聊；`user_context` 沿用既有 owner 范围，新草稿额外绑定 chat。未增加多用户或群聊能力，也不能通过卡片接管任意桌面 GUI 会话。

## 3. 代码与数据库

主要入口：

- `src/feishu/commands.ts`：项目选择、草稿消费、话题切换、详情和延迟消息路由。
- `src/feishu/conversation-ui.ts`：动作和通知 schema、话题标题、通知入队。
- `src/feishu/inbound.ts`：可信 nonce 查表、消息和动作身份校验。
- `src/feishu/sender.ts`：精简任务卡、项目及导航按钮、冻结回执。
- `src/persistence/migrations/004_conversation_ui.sql`：schema v4。
- `src/service/maintenance.ts`：新内容的保留及延迟消息依赖保护。

schema v4 新增 `feishu_drafts`，为 `feishu_commands` 增加固定路由字段，并扩展 `feishu_actions`，允许绑定项目/草稿的无任务导航动作。旧任务按钮及审批字段完整迁移；存在旧 worker/Gateway 租约时拒绝升级。没有新增依赖，也没有修改 Codex 自有数据库。

## 5. 部署后的人工验收

在线机器人已切换到新版。可先在“新版交互已上线”卡片点击「选择项目」→ `m5fixture`，再从 U03 开始；也可从 U02 的 `/项目` 入口开始。

| 用例           | 具体操作                                                                                                    | 预期                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| U01 初次引导   | 在无历史选择的隔离验收数据中，发送 `不使用工具、不读取文件、不联网。只回复 UXFIRSTOK。`，点击可执行测试项目 | 保存原消息，点击后只执行一次并返回 UXFIRSTOK      |
| U02 项目选择   | 发送 `/项目`，点击 `m5fixture`                                                                              | 显示所选项目和新话题提示，不立即执行任务          |
| U03 普通聊天   | 发送 `不使用工具、不读取文件、不联网。只回复 UXCHATOK。`                                                    | 收到精简任务卡和 UXCHATOK；无需项目 key 或任务 ID |
| U04 接着聊     | 在 U03 卡片点击「接着聊」，发送 `不使用工具、不读取文件、不联网。只回复 UXCONTINUEOK。`                     | 仍为 U03 的同一 thread，新 turn；提示当前话题     |
| U05 新话题     | 点击「新话题」，发送 `不使用工具、不读取文件、不联网。只回复 UXNEWOK。`                                     | 新建独立 thread，旧任务不取消                     |
| U06 引用旧卡   | 引用 U03 卡片发送 `不使用工具、不读取文件、不联网。只回复 UXREPLYOK。`                                      | 回到 U03 所属 thread，与最近选择无关              |
| U07 详情和切换 | 点击「查看详情」，随后点击「切换项目」                                                                      | 正确展示技术信息/项目列表；不新增模型任务         |
| U08 重复操作   | 在同一草稿选择卡重复点击项目，或快速点击两个项目                                                            | 只消费一次需求，只新增一个任务                    |

联调同时核对手机排版、点击回调、thread/turn、持久化记录和发送回执。不要仅凭卡片外观宣布无重复执行。
