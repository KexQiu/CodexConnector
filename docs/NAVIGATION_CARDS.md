# 项目、帮助、操作提示与任务列表

沿用飞书原生 JSON 2.0 分区布局，不添加前端依赖。2026-09-23 的 v9 部署记录见 [历史验收记录](./gates/navigation-cards-evidence.json)。2026-09-29 新增下述原卡更新能力，数据库升级为 v12；本轮真实飞书操作尚待验收，不沿用历史验收结论。

## 原卡更新（2026-09-29）

| 操作                                              | 显示方式                                                              |
| ------------------------------------------------- | --------------------------------------------------------------------- |
| 项目、任务、项目会话、无项目会话翻页              | 更新点击的原卡，保留消息 ID                                           |
| 会话列表切换到桌面只读列表                        | 原卡切换视图；“返回上一层”回到离开时的页码                            |

| 浏览按钮业务校验失败                              | 在原页面显示原因，保留浏览入口；旧版本按钮不允许覆盖新页面            |

直接输入 `/项目`、`/会话`、`/任务` 等命令，仍在聊天末尾创建新的入口。从任务卡或自动更新的当前面板进入详情/列表时，先打开独立浏览卡，随后复用该卡。任务进度、审批、终态及独立桌面任务完成通知维持原有投递方式。

### 更新与恢复规则

- v12 在 outbox 增加 `view_id` 和 `view_parent_id`，保存浏览卡版本及返回位置；不将浏览卡绑定为任务通知卡。原有 v1–v11 迁移保持不变。
- 同卡发送和更新按版本串行；未确认的 PATCH 进入 `unknown`，先核对回执，不自动转为 POST。其他卡片仍可正常投递。
- 更新完成后旧按钮失效；相同事件重投仍去重，新的有效按钮正常使用。更新中再次点击会提示等待更新或核对。
- 引用导航卡时记录收到消息当时的可见版本；路由只查看该版本的任务关联，不汇总历史页面按钮。包含多个会话或更新结果不确定时要求明确目标，不猜测续聊去向。
- 升级前已送达的普通导航卡首次点击可接入原卡更新；任务卡和主面板不会被接管为浏览卡。
- 返回恢复原页内容及页码，并重新标记当前选择；翻页会重新查询列表。长期保存的页面仍受当前目录、权限和会话归属校验约束。

### 本轮检查与试用

自动化覆盖原卡分页、逐层返回、选中反馈、无项目导航、额度刷新、重复事件/连续点击、引用回复、旧卡接入、未知回执恢复、任务/面板隔离、创建项目流程及 v11 → v12 回滚。完整回归 40 个测试文件、560 项通过；后端和桌面端类型检查、ESLint、Prettier 及差异检查通过。独立桌面构建位于 `.artifacts/card-navigation-20260929`；随包 Node v24.15.0 下 SQLite v12 迁移、创建卡片后原消息更新和完整性检查通过。

真实档案副本升级演练：23 张原业务表按全部原字段逐行摘要对比一致，8 个任务和 3 个会话保留，SQLite 完整性与外键检查通过。仅在离线副本移除服务租约，未改动或迁移正在运行的原数据库。证据保存在 `.artifacts/card-navigation-20260929/upgrade-check/evidence.json`。

试用步骤：

1. 退出当前开发 App，再在项目根目录运行 `pnpm desktop:dev` 并连接。启动前会备份并升级数据库，正在运行的旧实例会阻止升级。
2. 发送 `/项目`，点击“下一页”“上一页”：应只更新原卡，不增加新消息。选择一项后，应在原卡看到“当前”标记。
3. 发送 `/会话 无项目`，点击“接着聊”，再点击“查看详情” → “查看完整内容” → “返回上一层”：检查消息不增加，返回页码正确。
4. 发送 `/任务`，翻页后进入详情并返回：仍回到离开时那一页。点击当前面板的“刷新”时不应出现额外快照。
5. 发送 `/额度`，连续点击新按钮“刷新额度”：始终更新这一张额度卡。

若项目或会话不足一页，对应列表不会显示翻页按钮。以上步骤不会发起模型任务；不需要恢复此前搁置的退出/中断验收。手机视觉和真实飞书回调尚未在本轮验证。

## 使用方式

| 入口                              | 展示与行为                                                                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `/项目`、切换项目                 | 每项展示项目名称、key、当前标记和可执行/只读/路径失效状态；选择按钮紧邻所属项目。每页最多六项。                                |
| 兼容升级前保存的选项目草稿        | 顶部展示“已保存需求 · 尚未执行”、摘要及有效期；按钮明确标注“在此执行需求”，底部可取消。翻页不会执行，选择项目后才执行。        |
| `/帮助`                           | 分为日常对话、查看与切换、任务控制、更多用法；提供选择项目、当前会话和任务列表入口。                                           |
| `/任务`、`/任务 2`                | 不依赖当前选择，展示当前用户各项目的任务；每页四项，按最近更新时间排序，展示本轮需求、中文状态、项目、完整任务 ID 和详情按钮。 |
| `/状态`                           | 已选中或回复某任务卡时仍查看该任务；没有目标时展示新版任务列表。`/状态 任务ID` 保持原义。                                      |
| 取消、保存后续消息、命令拒绝/失败 | 按处理结果、关联信息和下一步展示；取消为灰色、等待为蓝色、命令拒绝为橙色、处理失败为红色。不会将命令拒绝写成模型执行失败。     |

- 项目选择会准备新话题，卡片明确说明。只读和路径失效的项目没有执行按钮；选择时仍重新检查权限和目录。
- 每轮需求单独列为一个任务；按会话合并查看仍使用 `/会话`。当前标记仅对应实际选中的任务。
- 查看列表、翻页、查看详情均不修改选中态，也不执行模型任务。任务列表最多展示最近更新的 2,000 项，更早记录可用任务 ID 查询。
- 页面变化或越界时提示重新打开列表；任务列表不会把其他用户的任务混入结果。
- ID 仅展示，不提供复制按钮、复制图标提示或网页跳转。
- 旧卡片不批量改写；重新发送命令取得新版。异常补充通知、桌面结束通知和审批正文的进一步细化不属于本轮范围。

## 历史 v9 实现与持久化

`src/feishu/navigation-cards.ts` 集中生成四类布局，`commands.ts` 负责接入已有命令。新增 `/任务 [页码]` 和只读 `tasks` 回调，避免改变 `/状态` 的已选中任务行为。

schema v8 → v9 的 `009_navigation_cards.sql` 只扩展卡片动作表，原行逐项保留。`tasks` 动作只能携带 0–499 的页码，不能携带任务、项目、审批、草稿或决定字段；其他动作的外键和约束保留。

项目列表导航与任务翻页按平台事件 ID 去重：同一事件重投不重复处理，新的点击可重新查看。项目选择、提交草稿、取消草稿和审批仍按原有幂等规则处理。所有回调继续校验用户、应用、租户、单聊、原消息和有效期。

## 手机检查

请在原机器人单聊依次发送：

1. `/项目`：确认项目逐项分隔、状态明确，按钮紧邻对应项目。本步仅查看，不必选择项目。
2. `/帮助`：确认四个分组清晰；点击“任务列表”。
3. `/任务`：确认每页最多四项，任务名称、中文状态和最近更新时间可见。点击“下一页”，再点任一项“查看详情”，确认对应任务 ID 一致。
4. `/任务 abc`：确认收到橙色“命令未执行”提示，说明页码格式，并有查看当前会话/任务列表的入口；这不会创建任务。

这些步骤只读或校验输入，不需要新建任务、提交审批或停止任务。真实 API 接受及回执核对不等于手机视觉验收。
