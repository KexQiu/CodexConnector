## 使用方式

- 点击机器人菜单「当前会话」，或者发送 `/当前`（`/面板` 也可），展示最新状态快照，并请求刷新后台维护的状态卡。
- 状态卡显示当前项目、当前话题、运行状态、排队消息数量和下一条普通消息去向，提供「切换项目」「新话题」「查看详情」「刷新面板」。没有话题时不显示详情，没有项目时只提供选择项目和刷新。
- 后台维护一张当前状态卡，项目/话题/任务状态变化时更新原消息；菜单和 `/当前` 的显式查询会另发一张快照，让用户无需翻找旧消息。快照不会持续更新，以后续查询或后台状态卡上的更新时间为准。
- 普通消息仍按原有选中态路由；查看面板或选择项目不会自动执行模型任务。
- 当前话题有执行中任务和后续排队任务时，状态显示执行中，排队数单列。任务尚未绑定会话时已保存的后续消息也计入排队数。其他话题的队列不混入当前话题。

## 飞书后台菜单配置

在**本项目配置的飞书应用**中操作，不要改同账号下其他应用：

1. 打开飞书开放平台 → 开发者后台 → 对应应用 → 机器人能力。
2. 启用「机器人自定义菜单」，保留已有不冲突入口，添加下列菜单。操作类型选「推送事件」，事件键逐字填写；这些是事件键，不是飞书消息正文。

| 菜单名称 | 事件键                  |
| -------- | ----------------------- |
| 当前会话 | `codex_current_context` |
| 切换项目 | `codex_switch_project`  |
| 新话题   | `codex_new_topic`       |

3. 在「事件与回调」中订阅「机器人自定义菜单事件」`application.bot.menu_v6`，沿用已配置的长连接接收方式，保留原有消息和卡片回调。
4. 按后台提示保存、发布/审批生效，重新打开机器人单聊。若后台提供菜单显示样式，选择适合当前客户端的固定/悬浮样式；实际位置由飞书客户端决定。
5. 点击「当前会话」应收到当前项目和话题快照；点击「切换项目」应出现项目选择卡；点击「新话题」应收到准备提示且不新增模型任务。

无需为菜单事件增加群管理或置顶权限。菜单配置尚未完成时，可以先用 `/当前`、`/项目`、`/新话题`。

## 持久化与可靠性

- `user_context`、`tasks` 继续作为唯一业务状态来源。`feishu_panels` 仅保存 owner/chat 对应的卡片消息 ID、发送时间、版本、快照摘要和刷新标记。
- schema v5 新增面板表、`outbox.panel_id` 和面板按钮动作；既有任务、按钮、草稿和选中态保持原值。面板与任务共用发送和回执核对机制，各自串行投递。
- 同一面板最多一个发送中/结果未知的操作；结果未知时核对原回执，不盲目重发或创建替代卡。其他任务通知仍能投递；用户显式查询仍可获得新的状态快照。
- 未发送的过时快照可合并，但保留平台限流退避时间。版本、消息 ID 和确认回执同事务保存，重启不会重复创建已经确认的状态卡。
- 面板导航按事件 ID 去重，允许用户再次点击同一个按钮；原任务执行、审批和草稿按钮沿用原来的 nonce 去重策略。
- 面板「新话题」「查看详情」绑定展示时的项目和任务。若处理点击时选中态已变化，旧操作不生效，返回最新状态，避免操作另一个会话。
- 菜单事件核对租户、应用和授权用户，白名单事件键转为固定命令，并路由到配置的专用单聊。客户端不能指定其他 chat/project/task；未知键不作为模型输入。菜单请求先落库，再由 SDK 确认接收。
- 当前 IM PATCH 接口仅允许更新发送后 14 天内的卡片，因此在第 13 天更换当前卡片；新卡确认送达后使旧卡导航失效。按钮有效期为 24 小时，无状态变化时也每 12 小时更新续期。服务长时间离线时，通过菜单或 `/当前` 重新进入。
- 只有平台明确拒绝已撤回、已删除或超出更新期限的卡片，才自动补建；权限等其他明确错误保留诊断记录，未知结果必须继续核对。状态卡包含更新时间，不能把离线期间旧显示当作实时状态。

官方依据：[菜单事件](https://open.feishu.cn/document/server-docs/application-v6/bot/events/menu)、[更新已发送的消息卡片](https://open.feishu.cn/document/server-docs/im-v1/message-card/patch)。

## 部署与验收

采用既有受控升级：先核对并排空任务/通知，归档原观察；停止自有服务、保存一致性备份和旧构建，归档旧 schema 自动备份，再部署已验证构建、迁移 v4→v5、重建清单并启动。禁止覆盖运行中的 dist。M6 通知保持关闭。

| 用例         | 操作                                 | 验收依据                                     |
| ------------ | ------------------------------------ | -------------------------------------------- |
| P01 当前状态 | 发送 `/当前` 或点击「当前会话」      | 快照项目/话题与 SQLite 相符；不新增模型任务  |
| P02 状态更新 | 选择项目或点击新话题                 | 后台状态卡 message_id 不变，内容随选中态更新 |
| P03 连续请求 | 在测试项目发两条普通消息             | 状态卡显示运行/排队，最终更新完成状态        |
| P04 旧按钮   | 切到其他话题后点击旧快照的「新话题」 | 提示当前会话已变化，不清空新选择             |
| P05 菜单重复 | 连续点击「当前会话」两次             | 两次独立点击均可查询；同事件重投只处理一次   |
| P06 重启     | 无在途任务时重启 Gateway             | 原状态卡关联保留，不重复创建                 |

过期轮换、丢失回执、限流、数据库失败及 v4 迁移在隔离测试覆盖，不将模拟 API 或推进测试时钟计为真实飞书故障验收。
