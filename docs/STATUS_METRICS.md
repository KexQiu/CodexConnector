# 会话模型、上下文统计与独立额度查询

最新交互：支持[会话列表、完整回复、带边框按钮及 ID 展示](./SESSION_NAVIGATION.md)，当前 schema v9；项目、帮助与任务列表见 [导航卡片说明](./NAVIGATION_CARDS.md)。

展示样式已升级为[分区摘要、详情和独立额度卡](./CARD_LAYOUT.md)，以下统计口径保持不变。

当前实现补齐新话题默认配置、既有会话的主动补读、历史 Token 快照恢复，并将账号额度独立为 `/额度`。升级使用 schema v7。最新验证见 [本轮证据](./gates/session-display-evidence.json)；[v6 证据](./gates/status-metrics-evidence.json)保留为历史记录。原面板交互见 [面板说明](./CONTEXT_PANEL.md)。

## 怎么使用

| 入口                       | 展示内容                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------ |
| `/当前`、`/面板`、刷新面板 | 当前项目、会话、任务状态、排队数量、模型、思考强度、最近请求输入和模型窗口           |
| 新话题（尚未执行）         | 当前项目默认模型和默认思考强度；上下文显示“尚未开始”                                 |
| 查看详情、`/状态 [任务ID]` | 会话信息，以及最近输出、缓存命中、累计消耗、模型和用量采样时间、已观察到的压缩时间   |
| `/额度`                    | Gateway 当前登录账号的剩余额度、真实窗口长度、北京时间重置时间、分组和积分、采样时间 |
| `/帮助`                    | 说明当前状态和额度的独立入口                                                         |

查询会话状态时先等待有界只读补取，再生成卡片；失败保留带时间和来源的已有数据。`/额度` 不需要选择项目，不改变当前项目/会话，也不创建模型任务。额度不再出现在会话面板或任务详情中，额度变动也不会触发会话面板更新。

## 数据口径

1. 新话题通过带项目 `cwd` 的 `config/read` 获取有效配置，并结合 `configRequirements/read` 的新会话默认值。模型或思考强度存在明确覆盖时，忽略这两项托管默认值。缺失时只使用 `model/list` 的默认模型或匹配模型的默认思考强度，不替自定义模型猜值。这里标注的是**默认配置**，会话建立后以实际会话元数据为准。
2. 已有会话模型来自 `thread/start`、`thread/resume`、`thread/read` 和 `thread/settings/updated`。`model/rerouted` 单独绑定具体 turn 展示，不将会话配置声称为每次后端推理的实际模型。
3. 实时统计来自 `thread/tokenUsage/updated`。`last.inputTokens` 是最近请求输入，`modelContextWindow` 是该次统计的模型窗口，`total.totalTokens` 是累计消耗。**累计消耗不等于上下文占用**；不计算伪精确占比。缓存命中是输入的子集，不重复加到输入总量。
4. 历史统计来自所选 Gateway 自有会话的本地 rollout 中 `token_count` 数字字段。恢复时可能重复记录继承用量，所以标注“历史快照”和原记录时间，不把它归因于最新一次执行。没有统计显示未记录/暂不可读/格式暂不支持等原因，不显示为 0。
5. 已完成的 `contextCompaction` 或历史 `compacted` 记录会清除更早的上下文用量，等待后续统计。旧历史不得覆盖更晚的实时数据或越过压缩边界。压缩时间仅表示实际观察到的记录。
6. `/额度` 读取 `account/read` 和 `account/rateLimits/read`。额度属于 Gateway App Server 当前账号的共享范围。剩余比例为 `clamp(100 - usedPercent, 0, 100)`；窗口长度取真实 `windowDurationMins`，不预设一定存在 5 小时/7 天窗口。
7. 优先采用 `rateLimitsByLimitId`，缺失或 null 时才用兼容字段。最多展开 8 个分组，不合并模型额度；积分不转换为金额。`resetsAt` 是 Unix 秒，以北京时间显示。到达重置时间仅提示待服务端确认，不自行变回 100% 或推断可恢复执行。
8. 缺失、未登录、不支持套餐额度、获取失败、旧数据分别展示。额度超过 3 分钟未成功刷新标注旧数据；模型和用量均保留采样时间，失败时不冒充实时数据。

官方接口依据：[App Server](https://learn.chatgpt.com/docs/app-server)、[配置和托管新会话默认值](https://learn.chatgpt.com/docs/config-file/config-reference)。协议以固定版本的生成类型和本机真实响应为准。

## 实现和边界

- schema v7 增加 `project_metrics`，按授权用户和项目保存默认模型等少量字段；v6 的 `session_metrics`、`account_metrics` 继续保存脱敏快照。持久化数据不含邮箱原文、凭据、配置全文或历史正文。
- 会话查询与额度查询使用独立读取通道和在途合并。后台每分钟采样；显式会话查询等待读取，额度主动查询最短间隔 10 秒，每个 RPC 最长 5 秒。慢额度请求不阻塞会话信息补读。账号变化使旧额度和旧在途响应失效。
- 历史适配器只读 `initialize` 返回的 Codex Home 下 `sessions` / `archived_sessions`，文件路径必须来自自有会话的 `thread/read`，并核对所属用户、会话 ID 和执行目录。拒绝越界路径、符号链接、硬链接和非普通文件。
- 读取上限为头部 512 KiB 和尾部 4 MiB，只提取数值与时间；跳过未写完行，格式异常安全降级。大文件尾部没有统计时不全盘扫描。该 JSONL 格式不是稳定公共 API，版本变化可能导致历史统计暂不可用；实时事件和已保存快照仍可展示。
- 状态读取不调用 `thread/resume`、不取得会话写锁、不执行模型任务。本文所述真实模型联调是单独的测试动作。
- 沿用原状态卡及其串行 outbox。普通统计更新节流 15 秒；任务状态、选择变化和显式刷新及时显示。模型查询不改变当前选中态。
- 升级必须先备份并停止两个自有服务，归档旧构建和观察记录，再迁移、启动和核验。禁止覆盖运行中的 dist；旧版本不可直接打开 v7 数据库。

## 手工验收步骤

在原机器人单聊按顺序发送，不需要在短时间内操作，也不需要重复点击：

1. `/当前`：当前为新话题时，应显示默认模型/思考强度和“尚未开始”；卡片不显示账号额度。
2. `/额度`：收到独立的“账号剩余额度”卡片，包含实际窗口、剩余百分比、重置时间和采样时间。
3. 在已有 Gateway 任务卡点击“接着聊”，再发 `/当前`：应显示该会话的模型和可用历史统计；若没有历史记录，应明确说明原因。此步骤不会执行任务。
4. 点击“查看详情”：核对最近输出、缓存命中和累计消耗；详情中也没有账号额度。
5. 需要验证新的实时用量时，选择 `m5fixture` 并开启新话题，发送：`不使用工具、不读取文件、不联网。只回复 SESSION_DISPLAY_CHECK_OK。` 完成后再发 `/当前` 并查看详情。

自动化用例覆盖历史文件身份/路径校验、截断/损坏/缺失、压缩后的更新顺序、缓存恢复、默认配置优先级、额度并发与消息去重。模拟压缩、账号切换和缺失窗口不能算作这些场景的真实服务验收；手机可见内容仍应单独确认。
