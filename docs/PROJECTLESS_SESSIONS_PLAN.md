# 无项目会话实施计划

制定日期：2026-09-28。状态：方案已整理，尚未实现。本计划基于当前工作区（含远程新建项目）制定；本次仅修改计划文档，不升级数据库、启动联调或切换部署。

## 1. 交付目标

用户无需先选择项目即可在飞书开始连续对话；也可以在项目选择列表中选择「无项目」，再新建会话或恢复某个历史无项目会话。

核心范围为 NP0–NP4：默认直接对话、独立选中态、无项目会话列表、续聊、状态与额度展示、排队和恢复。NP5「带入当前讨论」在核心闭环之后单独交付。

首版历史列表只展示当前身份与飞书单聊下、由 Gateway 创建的无项目会话。Codex 桌面端既有无项目会话的发现和接管不在本次范围内；不能把“支持同类能力”解释成可以直接操作桌面端原会话。

## 2. 已确定的交互

| 操作                         | 预期行为                                                                   |
| ---------------------------- | -------------------------------------------------------------------------- |
| 没有任何选中态时直接发送消息 | 创建无项目会话，立即提交这条需求，不再要求选择项目                         |
| 已有选中会话时继续发送消息   | 继续该会话；正在执行时按既有规则排队                                       |
| 打开 `/项目` 或「切换项目」  | 顶部固定展示「无项目」，下面是已有项目；标出当前选中项                     |
| 从项目切换到「无项目」       | 更新选中范围，展示无项目会话列表；等待选择历史会话或发送新需求             |
| 已在无项目会话，再打开其列表 | 保留当前会话选中态，不因查看列表清空上下文                                 |
| 「新建会话」                 | 清空当前范围内的会话选择，提示可发送第一条消息；此时不调用模型、不分配目录 |
| 尚未选择历史会话就直接发消息 | 在已选范围下创建新会话；不隐式恢复列表里的最近一条                         |
| 点击历史会话的「接着聊」     | 选中该会话，后续消息继续；点击本身不执行任务                               |
| `/会话`                      | 展示当前范围的会话；尚无选中态时展示无项目列表                             |
| `/新话题`                    | 在当前范围准备新会话；尚无选中态时使用无项目范围                           |
| `/当前`                      | 显示“项目：无项目”、会话标题、状态、模型、上下文及排队数量                 |
| `/额度`                      | 保持独立账号额度卡，不混入项目或会话卡                                     |
| 回复某张任务卡               | 以被回复任务的会话为目标，优先于当前选中态；归属无效时拒绝                 |

「无项目」固定入口出现在项目导航每一页的顶部，不计入真实项目数量，不占项目分页名额。无项目会话仍按当前会话卡分页规则展示，包含标题、摘要、最近更新时间、状态、当前标记和任务 ID。

进入普通项目时也提供该项目的会话列表及「新建会话」，保留“选完项目直接发消息即可开始”的快捷路径。无项目专属按钮统一使用「新建会话」「接着聊」，不显示虚构的项目 key 或内部目录。

切换范围、会话和翻页都不自动执行新任务，也不中断原会话的运行任务。旧版待选项目需求卡上的「在此执行需求」仍是明确的提交动作，不能与普通导航按钮混淆。

兼容命令：保留 `/选择 项目key`、`/新建 项目key 内容`、`/继续 任务ID 内容`。补充 `/选择 无项目`、`/会话 无项目`；“无项目”作为命令别名解析为结构化范围，不写进项目配置。

## 4. 会话模型与消息路由

### 4.1 明确的范围和会话身份

业务层采用以下概念，类型名称可按现有风格调整：

```ts
type ConversationScope = { kind: 'project'; projectKey: string } | { kind: 'projectless' };
```

新增 Gateway 本地会话登记，核心字段为 `conversation_id`、所属身份/会话、`scope_kind`、可空的 `project_key`、固定 `cwd`、目录身份、可空的 Codex `thread_id`、创建及更新时间。该 ID 在第一次模型请求前就存在，避免依赖尚未返回的 thread ID。

约束：项目会话必须有 projectKey，无项目会话必须没有 projectKey；未选中是独立状态，不能仅靠 `project_key = NULL` 推断。任务关联 conversation ID；重复请求继续定位同一个本地会话。

`user_context` 保存选中范围、可空的 conversation ID、当前任务引用及选择版本。按现有身份和 Chat ID 的授权边界校验；同一身份跨会话的记录不能混用。飞书上下文与本地 CLI 记录分别兼容，不能迁移时给所有无目标记录套上当前 Chat ID。

不在真实项目列表里塞入名为 `default`、`none` 或“无项目”的伪项目，也不让远程输入决定内部目录。

### 4.2 路由优先级

1. 已持久化的本条命令目标：重试只能继续原目标。
2. 显式命令、已验证的卡片动作或被回复任务。
3. 当前选中的会话，或已选范围下准备开始的新会话。
4. 确实没有选中态时，创建无项目会话。

首次解析消息目标时，在同一事务内持久化路由状态、范围、conversation ID 和任务关联。为命令增加明确的“尚未解析/已解析”状态，不能继续把 `target_project_key = NULL` 同时用于“尚未解析”和“无项目”。后续切换不会改变已排队消息的去向。

项目被移除、目录不可用、权限关闭、任务归属不匹配时返回明确错误，保留原目标，不降级到无项目执行。过期按钮也不触发默认创建。

远程新建项目的名称输入、审批回答等明确输入状态优先于普通聊天。等待项目名称时的一条普通消息仍作为名称处理；取消/过期行为沿用当前保护，不意外提交成无项目任务。

### 4.3 兼容旧数据

- 已有项目会话按所属身份和已有 thread ID 回填本地会话记录；已有线程但任务被清理的情况也要保留。
- 尚未建立 thread 的任务结合已有目标任务关联回填；无法证明同属一个会话时不合并。
- 旧的“待选择项目”草稿保持待处理，不因升级自动发送。
- 保留历史 request key、fingerprint、RPC intent、任务状态、outbox 和回执关联；新请求如需新的 fingerprint 格式，使用版本区分，不能重算旧值造成重复执行。
- 增加可空字段或重建表后，检查所有无列名的 `INSERT ... VALUES`、外键、索引和 Zod 消费字段。
- 迁移前停止服务并完成一致性备份；迁移失败整体回滚，不能一部分表使用新模型、一部分保留旧模型。

## 5. 运行目录、权限与并发

### 5.1 无项目仍有明确的运行目录

每个无项目会话分配独立、持久的空目录。建议在与 Gateway 数据目录分离的 App 管理目录下，按 profile ID/conversation ID 划分；开发版使用独立夹具目录。目录不进入本机项目配置，不作为远程新建项目的成果展示。

创建时记录规范路径和目录身份，恢复时核对；不使用系统临时目录承载长期会话，不因程序重启更换 cwd。已有会话目录丢失或被替换时提示核对，不静默重建并继续未知任务。

目录与 Gateway 凭据、配置、数据库、Codex Home 及可写项目范围隔离。更新本机路径校验，防止把无项目目录的父目录授权成普通可写项目或远程项目创建根目录。首版保留这些目录，不新增自动清理功能。

### 5.2 权限能力先验证

默认产品语义为普通对话：不继承任何项目的写入、命令、联网或外部工具授权。模型正常联网推理不受“工具禁止联网”影响。

NP0 必须验证固定 Codex 版本能否落实“禁用本地文件/命令工具与外部工具”的策略；只读沙箱仍可能允许文件读取或命令执行，不能等同于纯聊天。必须同时检查有效配置、线程/轮次策略和实际工具能力，不能以提示词约束或模型口头拒绝作为通过证据。

首版目标为禁用本地读写/命令、MCP、插件、应用、hooks、多 Agent 及网页搜索；具体受支持的配置项以 NP0 探针为准，不预先编造配置键。用户输入补充、任务取消等网关交互继续可用。无法落实限制时阻止无项目执行并显示原因，既有项目功能保持可用，不能静默改用更宽松策略。

本机 App 增加“无项目对话”设置与能力检查状态。通过验证的版本默认开启，可在本机关闭；不首发任意目录、任意写入或远程提升权限的开关。关闭后历史仍可查看，新增和续跑拒绝；必须停止后应用配置。

### 5.3 排队与恢复

- 项目任务和无项目任务共享现有全局并发上限。
- 相同 conversation ID 串行，包括 thread ID 尚未建立的首轮；不能让两条首次消息创建两个 thread。
- 不同无项目会话使用不同目录和锁，允许在全局名额内并行，不能因为共享一个默认 cwd 而全部串行。
- 项目会话继续使用现有 thread/checkout/嵌套目录锁。
- waiting、unknown、重连核对、停止与退出规则沿用现有可靠性语义；中断回执不等于终态。
- 第一轮 thread/start 回包丢失时保留未知状态，不重新创建一个会话或换目录重试。

核心预计约 4–8 个工程人日，以 NP0 结果修正，不包含等待人工联调和系统授权的时间。先完成 NP0，再按 NP1 → NP2 → NP3 → NP4 推进；NP5 不阻塞核心交付。无需新增运行时依赖或另建模型服务。

### NP5 的具体规则

选择/创建项目成功后可提供「带入当前讨论」和「直接开始新会话」。只有显式选择带入才准备摘要；摘要来源限定为用户选中的无项目会话已完成轮次，展示预览及来源后再提交。

在目标项目创建独立会话，带入需求、约束和已确认结论，不把它说成“完整历史原样迁移”。原无项目会话、thread ID、cwd、权限和历史不变；不原地修改执行目录，也不隐式接管桌面会话。目标权限未开放时，只允许保留准备内容，不执行项目任务。

| P12  | 本机关闭无项目对话并应用，尝试续聊；再重新开启                  | 关闭时历史可看但拒绝执行；开启后原会话可恢复                |
| P13  | 同时运行一个 Codex 桌面独立任务和一个无项目飞书任务，退出本 App | 仅处理网关持有的任务；桌面独立任务不受影响                  |

每个场景核对入站命令、conversation/thread/turn 关联、任务数量与通知记录；用户界面结果与持久化证据分别留存。NP0/NP4 真实验证结果另写入 `docs/gates/projectless-sessions.md`，不能用本计划代替验收报告。

## 9. 发布与完成条件

NP0 权限能力通过、NP1–NP3 完成且 NP4 关键场景验收后，再制作内部 DMG。先在独立数据副本测试升级，停止服务、备份完整配置和数据库后才切换用户档案。回退使用对应旧版本和迁移前的一致性备份，不让旧程序直接打开新 schema；保留升级后的数据供核对，不能无提示丢弃升级后新增对话。

核心交付完成需同时满足：首次无需选项目即可聊天；项目入口可选无项目；无项目历史可切换和续聊；原有项目、远程创建、任务控制和额度功能通过回归；权限、目录、并发、退出与恢复有证据。剩余真实验证项必须明确列出，不能以构建成功或测试数量代替联调完成。
