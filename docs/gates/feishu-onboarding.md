## F1–F3 实现约束

- 三个入口：扫码创建、已有机器人、手动配置。已有完整配置默认显示摘要；原五字段仍可编辑。
- 教程内置六步、路径示意、官方入口、复制权限/事件和完成标准。勾选只记录人为操作进度。
- `feishu-setup.json` 使用 600 权限的原子文件，包含加密待配置凭据、教程进度、与配置指纹绑定的检查记录；不会新增任务数据库迁移。
- Secret 只在主进程 safeStorage 与 Node 私有 IPC 中出现。注册进度与 UI 快照不包含 Secret；不转发 SDK/Axios 错误内容。
- 收到凭据先保存待配置档案；取消与重开保留它。没有成功授权时不自动重建应用，也不恢复过期二维码。
- 绑定码采用 24 字节随机值（192 位）、5 分钟有效、一次消费。仅接受目标应用的用户单聊文本。正式收件入口永久忽略 `/connector-bind` 指令，包括无效和过期重放。
- 配置进程不实例化任务执行器，不发送测试消息。配置 socket 与网关共用 App ID 锁，同时遵守已有桌面版本的服务租约。
- 锁是独立的用户私有连接租约文件，按应用哈希分隔；持有者存活时拒绝抢占，正常关闭释放，进程死亡后可恢复。并非任务数据迁移。
- 注册与检查在后台按操作 ID 运行；开始调用立即返回。取消/退出不排在扫码轮询后等待。注册 HTTP 本身也带中止信号和单次超时。
- 合并待配置身份前先刷新草稿，校验草稿 revision；仅替换飞书字段，保留并发编辑的项目内容，随后按原有应用配置流程生效。
- 检查最长 30 秒：token、单页历史接口、长连接握手。同配置的在线连接可以复用；临时连接在成功、失败和取消时关闭。
- 通过、失败、跳过、修改后待验证分别展示。基础检查不声称验证了消息订阅与卡片回调；跳过不绕过正式启动前的历史权限和 Codex 检查。
- 右上角反馈与步骤内详情并存；二维码、绑定指令和检查结果出现时自动滚动到对应位置。配置运行期间不能应用新配置或启动正式服务。

## 后续真实验收步骤

1. 独立档案打开新版 App；创建唯一测试机器人，完成扫码；确认 App 只显示 App ID、不回显 Secret；关闭重开能继续配置同一个应用。
2. 对照教程核对机器人能力、三项消息权限、消息事件、卡片回调。若平台允许自动配置开发设置，再记录所需管理权限与实际发布结果；否则沿用手动步骤。
3. 点击“绑定单聊”，保持配置连接在线，在平台分别保存事件与回调的长连接模式并发布。向新机器人发送本页一次性指令；核对绑定账号与 Chat ID，保存到当前配置。
4. 点击“检查连接”，确认三项结果和时间；期间没有收到测试消息。取消/跳过一次，核对连接已关闭、状态为未验证；正式启动仍需通过必要检查。
5. 开发验收单独发送真实普通消息并点击卡片，核对原卡更新与回执读取。F3 面向最终用户不要求此步骤。
6. 使用另一专用已有测试机器人重复补配，确保原权限/订阅和原绑定未被删除；Webhook 切换由用户在平台确认。
7. 核对原档案仍可恢复，当前机器人未被意外改绑，测试连接退出后无残留进程；通过后再更新“推荐”标识并制作内部安装包。

## 失败恢复

- 授权拒绝/过期：可重新生成；授权尚未成功时不记录为配置完成。
- 扫码后卡在发布/审批：已加密保存应用，稍后继续；不要重新新建。
- 断网/长连接未就绪：取消配置连接，恢复网络后重新绑定；旧指令不再有效。
- 无扫码用户 ID：必须本机确认候选账号；拒绝或取消不替换原绑定。
- Secret 无法解密：重新授权 Keychain 或在已有机器人入口手动填写；不能明文降级。
- 草稿发生并发变化：刷新并重试合并，不覆盖项目编辑。
- 连接锁冲突：在本机停止占用该 App ID 的服务；不得按进程名批量终止。
- F3 失败：修复具体项后重试，或跳过并保留“未验证”；启动必要检查仍有效。
