# 飞书卡片分区展示

2026-09-23 上线。卡片使用飞书原生 JSON 2.0 组件，不依赖网页、图片或额外前端依赖。初版数据库为 schema v7；当前已升级到 v9，并完成[会话导航、全文分页、按钮边框与原卡 ID 展示](./SESSION_NAVIGATION.md)。

## 使用方式

| 入口                           | 主要内容                                                   | 操作                                                   |
| ------------------------------ | ---------------------------------------------------------- | ------------------------------------------------------ |
| 常驻会话面板、`/当前`、`/面板` | 项目、话题、执行状态，双列模型/思考强度、最近输入/模型窗口 | 查看详情、新话题、切换项目、刷新面板                   |
| 新话题/切换话题提示            | 当前选择、模型设置、后续消息去向                           | 新话题、切换项目                                       |
| 任务进度/结果卡                | 话题、状态、突出异常、独立结果区                           | 详情、完整 ID 展示；按状态提供接着聊、全文、刷新和停止 |
| 查看详情、`/状态 任务ID`       | 最近输出、缓存命中、累计消耗、采样时间、任务标识、目录     | 接着聊、新话题                                         |
| `/额度`                        | 独立分组的剩余百分比、进度条、重置时间与采样时间           | 再发 `/额度` 刷新                                      |

没有排队消息时不显示“0 条排队”。新话题显示默认模型和“尚未开始”，已有会话显示实际会话设置。缺失数据写明“尚未获取”或“未提供”，不补零。

一张卡最多突出一个主按钮；切换、刷新使用带边框的次要按钮，停止任务用红色按钮。等待审批或输入使用橙色状态，审批范围和所有决定按钮放在同一个区域，所有决定保持相同视觉权重。失败原因和控制请求状态仍可见。

额度进度条按十格近似展示，百分比保留一位小数；窗口时长使用服务端实际返回值。旧数据、无法使用常规额度、重置时间已到但尚未确认均有明确说明。没有窗口数据就没有进度条。会话用量不画占用比例，因为最近请求输入和累计消耗均不等于实时上下文占用。

## 实现与兼容性

- `card-layout.ts` 定义可选布局快照和原生组件渲染；分隔线、标题、弱化说明、每行两列字段/按钮形成层次。用户文本和模型输出继续转义，只有应用生成的格式能进入 Markdown。
- `metrics-layout.ts` 将已有会话/账号缓存投影为展示区块；`task-layout.ts` 生成任务摘要与详情。获取数据、权限判断和命令分发没有新增链路。
- `outbox.payload.layout` 可选，旧通知继续按原文本格式展示。已冻结的 `wire_content` 不重新渲染，重试期间 nonce 和回执均不改变。
- 面板快照 hash 包含布局版本与区块；已有面板沿原 message ID 更新。额度依旧不进入面板 hash，不因账号额度变动刷新会话卡。
- 标题中的完整 `GW-…` 回执保留。飞书 IM GET/LIST 可能只返回卡片标题预览，隐藏或缩短这个标识会影响未知发送结果的核对。正文末尾也保留回执。
- 审批文本、授权范围和过期时间完整保留；按钮的身份、会话、任务、期限和幂等校验不变。序列化卡片仍受 28 KB 上限保护。
- 任务结果从开头展示，长结果可在飞书分页查看当前保留的全文。项目、帮助、操作提示和任务列表已接入分区展示，见 [导航卡片说明](./NAVIGATION_CARDS.md)。异常补充通知和桌面结束通知仍使用文本正文。

组件依据：[Markdown](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/rich-text)、[分栏](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/containers/column-set)、[按钮](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/interactive-components/button)、[分割线](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/content-components/divider)。

- 飞书专用单聊只新发一张“虚构数据”预览卡，原地更新验证摘要、详情、额度、审批四种布局；按钮为禁用示例，不含真实审批。
- 故意丢弃真实发送的成功回包，持久化为 unknown 后通过历史回执核对为 delivered；只有一次发送。
- 生产两个服务已重启就绪，原常驻面板 PATCH 成功，远程 GET 预览包含本轮回执；schema v7、任务数量及选中态不变。生产数据库未迁移。
- 接口接受与 GET 回执不等于手机视觉验收。用户仍需核对下面三种卡片。

在原飞书机器人单聊分开发送：

```text
/当前
```

确认项目与话题位于顶部，模型/思考强度和用量成组显示；当前为新话题时不显示伪造的 Token 数。

```text
/额度
```

确认独立额度卡有剩余百分比、对应进度条、重置时间及采样时间。数据不可用时应显示原因。

```text
/状态 76356b42
```

这是本机已有的测试任务，不会重跑任务。确认详情中显示用量分组和任务信息区；与当前主卡区别明确。可点击“刷新面板”验证回调；不要为验收展示而点击真实审批或停止按钮。
