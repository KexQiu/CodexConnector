# CodexConnector 0.1.1-beta.2

日期：2026-10-08。macOS Apple Silicon 内部测试修复版。

## 修复安装后无法打开

本机已安装 beta.1 的崩溃报告 `CodexConnector-2026-10-08-110819.ips` 明确记录：`DYLD / Library missing`，实际原因为 Electron 框架加载时出现 `different Team IDs`。App 与框架的文件都存在，严格签名校验也通过，但二者使用 ad-hoc 签名、没有 Team ID；主进程启用了 Hardened Runtime，却未声明允许加载此类动态库。

签名配置此前只为随包 Node 设置了 `com.apple.security.cs.disable-library-validation`。本版为 Electron 主程序、辅助进程与随包二进制统一补齐该 entitlement，同时保留 Hardened Runtime、渲染沙箱及上下文隔离。不修改系统 Gatekeeper 或 SIP，也不删除用户数据。

[Apple 的 Library Validation 说明](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.cs.disable-library-validation)解释了此限制：库需要由 Apple 或与主程序相同的 Team ID 签名。该例外仅用于目前 ad-hoc 内部包；正式证书签名、公证时应重新评估。

## 补齐安装包启动门禁

`pnpm desktop:release` 在静态签名检查之后，启动最终 `.app/Contents/MacOS/CodexConnector --connector-smoke-test`，失败时不生成成功的 `release.json`。

- 由 App 自行创建随机临时档案，不读取正式活动配置；退出清理该档案。
- 实际加载 Electron 框架、BrowserWindow、preload 与 React 页面；确认准备清单和准确版本已渲染。
- 通过 preload 的正式 IPC 读取状态，确认未配置、服务停止、飞书未连接；不启动模型任务。
- 结束自有后端并退出；无成功回执、渲染失败或超时均判定失败。
- 单独复测命令：`node scripts/desktop-smoke.mjs /路径/CodexConnector.app`。

此前 beta.1 只核对了签名、镜像和独立 Node/后端，没有验证最终 Electron 主程序。其“源码外运行通过”不能等同于完整桌面启动通过，本版明确补上这一缺口。

## 更新方式

退出旧版，打开本版 DMG，把 CodexConnector 拖到“应用程序”并替换，再从“应用程序”启动。应用数据继续使用 `~/Library/Application Support/CodexConnector`，不需要删除或重填飞书配置。本次修复不自动替换本机 App；原 beta.1 产物保留用于复现，不建议继续使用。

依旧是未公证的内部测试版。签名加载错误修复不代表已经获得 Apple Developer ID 或通过公证；这与本次崩溃是不同的验收项。
