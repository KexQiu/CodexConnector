# CodexConnector macOS App

首版是 Apple Silicon 内部测试版。App 自带 Node 24.15.0 和后端依赖；安装者不需要 Node、pnpm 或源码。仍需安装并登录兼容的 Codex：生成协议基线为 `codex-cli 0.155.0-alpha.9.2`，运行时按实际协议判断兼容。旧基线和 `0.158.0-alpha.2.1` 均可通过核心协议检查；后者尚未完成完整真实联调。未知版本在所需契约兼容时可以启动，契约变化或导出失败会阻止启动；没有关闭检查。详见 [多版本兼容策略](./CODEX_COMPATIBILITY.md)。

当前实现、测试结果与待验收项见 [D1–D4 记录](./gates/D1-D4-desktop.md)。

## 安装与使用

1. 打开 `apps/desktop/out/make` 内的 DMG，将 **CodexConnector.app** 拖到“应用程序”。这是使用 ad-hoc 签名的内部包，尚未完成 Developer ID 签名与公证；macOS 可能要求在“系统设置 → 隐私与安全性”确认打开。
2. 打开 App。它默认停止，不会自动接收飞书消息。
3. 首次进入 **准备清单**，分别查看 Codex 环境、飞书连接、本地项目。本地项目可选；允许普通聊天且能力检查通过时，无项目也可使用。
4. **应用设置 → Codex 环境** 可选择可执行文件、检查版本与协议。登录仍在 Codex 桌面端完成，启动时核对登录状态。
5. **飞书连接** 提供“创建新机器人”和“连接已有机器人”，按四步完成；原始身份字段和手动教程保留在对应步骤中。完成只保存飞书配置，其他页面修改仍为草稿。
6. 在 **本地项目** 添加或授权目录；新发现的项目默认禁止执行。项目权限、并发以及 Codex 等修改在对应页面应用后，回总览点击 **启动连接**。配置完成不会自动启动。

飞书后台仍需完成应用发布、消息事件订阅、长连接模式、`card.action.trigger` 回调和消息权限。完整证据与待验收项目见 [F0–F3 验收记录](./gates/feishu-onboarding.md)。扫码尚未完成真实端到端验收，不标记为推荐。

## 飞书接入与日常管理

首次接入按四步进行，底部始终提供当前主要操作及“稍后继续”：

1. **接入机器人**：新建时填写名称并扫码（试用）；已有应用填写 App ID、Secret，也可以扫码补齐权限与订阅。扫码完成立即加密保存凭据。手动创建教程作为本步骤的备选路径。
2. **完成飞书设置**：按机器人能力、最小权限、事件与回调、发布四项核对后台。页面保持独立配置连接，可在飞书后台保存长连接设置；手工确认仅记录操作，不等于检测成功。已有 Webhook 需在平台确认切换。
3. **绑定单聊**：此时才生成 5 分钟有效的一次性指令，复制后在机器人单聊发送。有扫码账号时核对发送者；无扫码账号时回到本机确认候选用户与 Chat ID。已有绑定可沿用，也能选择重新绑定或手动填写身份字段。
4. **检查并保存**：最长 30 秒检查凭据、单聊历史读取和长连接；不发送消息、创建卡片或执行模型任务。通过后自动保存；失败可修复后重试，也可点击“跳过检查，直接保存”。

保存只应用飞书字段和 Secret。项目、权限、并发及 Codex 等未应用修改继续保留；首次建立活动配置使用安全默认值，不自动授予草稿中的项目权限。保存后回到连接管理页，正式连接仍需手动启动。

已配置用户默认看到管理页：机器人及绑定信息、基础检查记录、正式运行状态分别展示。“修改凭据”“重新绑定”直接进入对应步骤；“更换机器人”进入完整流程。基础检查不代表真实消息订阅与卡片回调已完成验证，跳过也不会绕过启动必需检查。

进度自动保存；“稍后继续”、离开飞书页或退出 App 会结束临时连接。返回飞书后台浏览器不会关闭配置连接。重开 App 后点击“继续配置”，保留应用凭据和步骤，但不恢复旧二维码或旧绑定码。配置连接最长 30 分钟；绑定码过期可以原位重新生成，不必重复创建应用。

正式服务运行中可以编辑并缓存；需要扫码、绑定或保存生效时，点击页面内“停止服务并继续”。存在未完成任务时沿用停止确认，不会静默中断任务。更换 App ID 清除待配置记录中的旧 Secret 和旧绑定，活动配置在最终保存前不变，原身份历史仍保留。

完整教程由帮助抽屉打开，支持离线查看；平台入口和二维码需要联网。二维码、绑定指令及主动检查结果出现时仅定位一次，不会随着倒计时或状态推送反复滚动。

## 项目自动刷新与已有开发服务

- App 打开时、回到前台时、进入项目页面时及前台每隔 30 秒，自动读取本机 Codex 项目。支持 `CODEX_HOME`，默认 `~/.codex`；不需要启动网关。
- 使用已验证 Codex 版本的项目登记表，只读目录与名称；旧版本回退读取本地 UI 项目列表。不会读取任务正文、凭据或修改 Codex 数据。后续 Codex 数据结构变化时提示读取失败，仍可手动添加。
- 按规范目录去重，保留当前项目的名称、标识及权限，不覆盖编辑。新发现的 Codex 项目默认禁止执行、禁止联网；远程创建的项目保留本机预设权限。列表自动缓存到本机；本机修改停止后应用才会生效，不自动改动运行中的网关。
- 移除项目后，刷新不会重新添加；自动缓存完成后重开仍记住移除。需要恢复时通过“添加项目”再次选择该目录。Codex 删除的项目不会自动删除 App 中已经配置的项目。
- 目录不存在/暂不可用时跳过新发现条目，保留已配置条目并显示提示；最多保留 100 个项目。
- 已配置但不可用的目录会在项目列表中标记。禁止远程执行的项目不阻止连接启动，也不会自动删除或重建目录；已授权项目仍须恢复目录，或在本机关闭远程执行并应用配置后才能启动。
- CLI 尚未发布，App 不提供 CLI 配置/历史导入。已有开发用 LaunchAgent 仍运行时，启动检查会阻止重复连接；请在本机停止原服务后再启动 App。App 不会自动迁移或停止它们。

## 从飞书新建项目

1. 在 App **本地项目 → 远程新建项目** 打开「允许飞书创建项目」。旧配置默认关闭。
2. 选择独立的已有保存目录，例如 `~/Code/RemoteProjects`。可先在 Finder 新建该目录；它不能位于已有项目内，也不能与 App 配置、网关数据或 Codex 数据目录重叠。
3. 设置新项目默认权限。默认仅创建目录、不执行任务；希望创建后直接开发时，选择「允许修改项目文件」。任务联网另行开启。
4. 停止服务，点击 **应用配置 → 启动连接**。运行期间编辑只缓存草稿，不改变当前授权。
5. 飞书发送 `/项目`，点击「新建项目」，收到提示后直接回复名称，例如 `旅行网站`。也可以一次发送 `/新建项目 旅行网站`。
6. 收到「项目已创建」卡片后，新项目已被选中。已授予执行权限时，直接发送任务需求即可。创建本身只生成空目录，不执行模型任务、不初始化 Git、不克隆仓库。

名称支持中文、字母、数字、空格、短横线和下划线，最多 64 个字符；不能填写路径。同名目录不会覆盖或自动接管。名称输入等待 30 分钟，可点「取消创建」或发送 `/取消创建` 退出；打开项目列表或选择已有项目也会退出名称输入。过期后的名称消息会被拦截并提示，不会变成任务。

远程项目会持久保存到当前身份与会话的数据档案，App 项目列表自动刷新展示；可以在本机修改名称、标识和权限，停止后应用。关闭创建开关或修改默认权限仅影响以后的创建，已有项目的权限在各自项目行修改。「移除」不删除文件，应用后停止加载该项目。

消息重发按请求去重；服务重启恢复登记记录。目录身份改变时拒绝执行旧项目。若在创建目录和保存记录之间异常退出，目录保留、结果显示待核对；在本机检查后通过「添加项目」选择该目录，系统不会自动覆盖或清理它。保存目录下累计登记最多 100 次创建（含待核对记录）。这套登记属于 CodexConnector，不会写入 Codex 桌面端内部项目数据库。

手动验收：创建一个唯一名称的项目 → 收到成功卡 → 发送「不使用工具、不读取文件、不联网。只回复 REMOTE_PROJECT_OK。」→ 确认完成卡；关闭重开 App 后，从 `/项目` 重新选择该项目并继续对话。重复发送同名创建命令应提示已存在，本机只保留一个目录。

## 开机自启

在 **应用设置 → 开机自启** 中打开“登录 Mac 后自动打开 CodexConnector”。这里指当前用户登录后的启动：开机但尚未登录时不会运行。

- 仅安装版 macOS App 可设置，请先从 DMG 将 App 拖到“应用程序”。开发模式 `pnpm desktop:dev` 不会把 Electron 或源码路径加入登录项。
- 开关即时写入 macOS 登录项，不需要保存草稿或应用飞书配置；由系统持久保存，App 不会根据旧缓存重新开启已被系统关闭的设置。
- 系统要求批准时显示“等待系统批准”，在系统设置的“登录项”中允许 CodexConnector 后返回 App，状态自动刷新，也可手动点击“刷新系统状态”。等待批准不代表自启已生效。
- 登录后显示控制台，飞书仍需点击“启动连接”。退出/关闭 App 仍会停止网关；本功能不增加后台隐藏运行或 LaunchAgent 常驻服务。
- 关闭开关即可取消登录后启动。卸载或移动 App 后请在系统登录项中核对；在“应用程序”之外不能新增登录项，但可以关闭本 App 已有的登录项。
- 首次不主动开启，请按需自行设置。内部包尚未正式签名公证，自启的系统批准和实际重新登录仍需在安装环境验收。

## 操作反馈

总览、飞书连接、本地项目、应用设置、日志与诊断和配置向导共用窗口右上角悬浮提示。滚动到页面底部时，保存、应用配置和检查失败仍会立即显示，不会跳回页面顶部；检查详情与帮助说明继续保留在对应表单中。

- 操作中的提示持续到操作结束。成功提示约 6 秒后消失，鼠标悬停或键盘聚焦时暂停关闭；错误提示不会自动消失，可以手动关闭或在重新操作后更新。
- 自动缓存失败会单独保留“重试保存”入口，成功保存后移除。较长的错误文本可在提示内滚动，不会将关闭按钮挤出窗口。
- 项目自动刷新和运行状态推送的同一错误不会反复弹出；恢复正常后清除对应错误。手动点击刷新会再次显示本次结果。
- 总览和配置向导的“启动连接”旁会直接显示不可启动的原因，包括首次配置未应用、存在待应用修改、操作进行中或连接尚未停止，并提供继续配置或检查应用的入口。项目列表为空时展示“添加本地项目”；已应用的空项目配置仍可连接，支持之后添加项目或使用已开启的远程新建功能。
- 输入框与下拉菜单使用统一的自建组件。项目权限选项附带说明和选中标记；菜单支持方向键、Home/End、Enter/空格确认、Escape 取消、Tab 离开与输入首字符定位。菜单会根据窗口剩余空间向上或向下展开。

## 配置自动缓存

填写 Codex 路径、项目及权限、并发数时，停止输入 **600 毫秒**后自动保存本地草稿，离开输入框或 App 时也会触发保存。飞书接入使用独立草稿，停止输入 **500 毫秒**后缓存，离开流程或退出时等待写入完成。字段尚未填齐、没有联网时仍能缓存；无需点击“立即保存”，其他配置页保留该按钮用于立即落盘或失败重试。

- 顶部展示“正在缓存”“已缓存 · 待应用”或“缓存失败”。再次打开 App 自动恢复草稿，Secret 只显示已保存状态，不回显。
- 新安装自动发现的项目和移除记录也会缓存。配置缓存与服务运行配置分开，仍需停止服务后点击“应用配置”。
- 全局草稿使用原子文件 `draft.json`，飞书流程草稿使用 `feishu-setup.json`；Secret 经 safeStorage 加密，不写浏览器 localStorage 或明文凭据。未替换 Secret 的普通编辑复用已有密文。
- 正常关闭窗口或 `⌘Q` 会等待缓存写入完成。保存失败或未确认时保留窗口，提示重试；取消退出后可以继续编辑。
- 强制结束进程/断电无法等待保存，最后尚未完成的输入可能丢失；此前成功缓存保持可恢复。

## 数据与退出规则

- 正式 App 数据目录：`~/Library/Application Support/CodexConnector`。开发版使用项目 `.artifacts/desktop-user-data`，两者隔离。
- Secret 使用 `safeStorage` 加密，密钥由 macOS Keychain 管理。密钥不可用时失败并提示，不降级保存明文。内部包更新可能要求重新授予 Keychain 访问。
- `feishu-setup.json` 保存飞书独立草稿、扫码待配置应用的加密凭据、流程步骤、教程进度和检查记录。绑定验证码与授权二维码不跨重启恢复，不写入任务数据库；退出会取消轮询并关闭配置连接。
- `feishu-commit.json` 是仅应用飞书时的可恢复提交记录，保存加密后的活动配置与全局草稿；提交完成后删除，意外中断后在下次读取时继续完成，不丢失其他草稿。
- `active.json` 是配置与加密 Secret 的同一个原子快照；`draft.json` 是尚未应用的草稿。目录权限 700，文件权限 600。
- 更换 App ID、Tenant Key、Open ID 或 Chat ID 会切换到隔离档案；原历史保留。Secret 更新不会改变档案。
- 运行时可保存草稿，应用配置必须停止服务。存在未决任务时拒绝应用，防止修改项目目录/身份后执行旧工作。
- 新版启动前检查任务数据库版本。需要升级时，先核对完整性、已有迁移记录和旧服务/任务状态，在 `backups/before-upgrade-*.sqlite` 留下完整备份，再在同一事务内清理已确认退出进程的运行锁并升级。权限不足、备份失败、进程仍在运行或任务未完成时拒绝升级；升级失败回滚结构和锁，不清空历史或重复执行任务。
- 点窗口关闭或 `⌘Q` 会退出。存在未完成任务时确认后取消队列并中断网关持有的运行任务，之后停止自有后端。不关闭 Codex 桌面端，不终止它独立运行的任务。
- RPC 中断应答不等于任务终态；未确认任务保持 `unknown` 和执行锁，重新启动时核对，不盲目重放。
- App 主进程退出导致私有 IPC 断开，后端会自行清理。自有进程组中的子进程也会停止。若后端本身被 SIGKILL、磁盘损坏或无法证明旧进程已退出，租约会阻止抢占，需要人工核对。

## 开发与打包

构建者需要 macOS arm64、Node 22.14+（22.x）或 24.x、pnpm 11.20.0、Xcode Command Line Tools 和 Python。App 内置后端 Node 仍固定为 24.15.0；构建脚本会独立准备并校验，不要求宿主版本相同。安装者不需要这些工具。完整策略和双版本回归见 [Node 兼容说明](./NODE_COMPATIBILITY.md)。

```sh
pnpm install --ignore-scripts
pnpm desktop:setup
pnpm desktop:build
pnpm --filter @codexconnector/desktop start
pnpm desktop:make
```

`desktop:setup` 只准备固定版本 Electron 并校验官方 SHA-256，同时编译 DMG 所需的 `macos-alias`、`fs-xattr` 两个构建辅助模块。保持全局依赖安装脚本关闭。若下载中断，删除 `.artifacts/electron-download` 中未完成的对应 ZIP 后重试；替代镜像文件也必须通过固定官方校验值。

需要保护正在运行的开发产物时，可以指定独立构建目录：

```sh
CONNECTOR_DESKTOP_BUILD_ROOT="$PWD/.artifacts/feishu-redesign-20260929" pnpm desktop:build
CONNECTOR_DEV_RUNTIME_ROOT="$PWD/.artifacts/feishu-redesign-20260929/desktop-runtime" \
CONNECTOR_DEV_DATA_ROOT="$PWD/.artifacts/feishu-redesign-20260929/manual-profile" \
  apps/desktop/node_modules/.bin/electron .artifacts/feishu-redesign-20260929/app
```

默认的 `desktop:build` 生成独立 `.artifacts/desktop-runtime` 和 `apps/desktop/dist`，不会覆盖现有 CLI 服务使用的根 `dist`。后端生产依赖被实体化，原生 SQLite 由随包 Node 加载，不由 Electron 加载。

```sh
pnpm typecheck
pnpm desktop:typecheck
pnpm lint
pnpm format:check
pnpm test
pnpm desktop:build
```

本地 socket 测试需要允许 loopback / Unix socket 监听的终端。此处不用包含根构建的 `pnpm verify`，避免覆盖现有常驻部署。

### 图标资源

界面线性图标统一维护在 `apps/desktop/src/icons.tsx`；连接环标识的源文件为 `apps/desktop/public/connector-mark.svg`。应用图标使用同一标识，开发时显示在 Dock，打包后使用 `apps/desktop/assets/app-icon.icns`。PNG 和 ICNS 已随源码保存，常规构建无需重新生成。

修改标识后，在 macOS 上执行 `pnpm --filter @codexconnector/desktop icons`，使用现有 Electron 和系统 `iconutil` 重新生成 SVG、PNG 及包含普通/Retina 尺寸的 ICNS，无额外依赖。生成器只启动独立的隐藏渲染窗口，不加载网关或用户配置。重新构建并启动开发 App 可查看 Dock 图标；已安装的 App 需重新打包安装后才会更新。

## 验收清单

自动化覆盖配置加密边界、草稿、身份隔离、CLI 兼容、私有文件、退出竞态、任务终态、进程组清理、项目自动发现、去重与移除记忆。测试使用夹具，不代表真实飞书和模型联调通过。

| 编号 | 操作                                                                      | 预期                                                 |
| ---- | ------------------------------------------------------------------------- | ---------------------------------------------------- |
| A01  | 在没有 Node/pnpm 的另一台 Apple Silicon Mac 安装 DMG                      | 能打开配置向导；内置运行环境就绪                     |
| A02  | 分别填写不存在的 Codex 路径、错误 Secret                                  | 显示可定位错误，不显示已连接                         |
| A03  | 修改字段并等待“已缓存”，不手动保存，关闭重开；再应用配置                  | 自动恢复配置；Secret 不回显；应用后可启动            |
| A04  | 打开项目页，编辑名称、移除一项，然后刷新并保存重开                        | 已有项目自动加载；编辑保留；移除项不重新出现         |
| A05  | 启动后在机器人单聊发送 `/项目`                                            | 收到正确项目列表                                     |
| A06  | 发送 `/新建 m5fixture 不使用工具、不读取文件、不联网。只回复 APP_V1_OK。` | 正常回卡，任务完成；测试者先配置自己的项目标识       |
| A07  | 在 Codex 桌面端启动一个独立长任务；同时从飞书启动一个长任务，然后退出 App | 确认后仅飞书任务停止；桌面任务继续                   |
| A08  | 重新打开 App，再启动                                                      | 已完成/已中断工作不重复执行，未知工作被核对          |
| A09  | 断网后联网、睡眠后唤醒                                                    | 状态正确变化并恢复，不重复执行任务                   |
| A10  | 将 App 移到含空格/中文的新路径，重新打开                                  | 不依赖源码或构建时的 Node 路径                       |
| A11  | 安装到“应用程序”，打开“应用设置”，开启自启；按系统提示批准                | 显示系统真实状态；待批准时不显示已开启               |
| A12  | 保存工作后注销并重新登录 Mac，再关闭自启并重复登录                        | 开启时显示控制台且网关停止；关闭后不会因本登录项打开 |
